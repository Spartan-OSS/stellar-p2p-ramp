# Contributing

Run the README commands before opening a PR. Choose one backlog item; explain your implementation approach and ask the maintainer for assignment before substantial work. Keep changes scoped and include tests for money, authorisation, concurrency and state transitions.

Never commit keys, real identity documents, bank details or payment receipts. Use synthetic fixtures and testnet assets. Do not import code from a public repository without a confirmed licence and preserved notices.

The maintainer reviews PRs and merges changes. Contract and payment changes require explicit review of authorisation, fund conservation and failure paths. Design issues can be resolved with a reviewed specification; implementation issues require working code and the acceptance evidence stated in the issue.

Before accepting contributors, the maintainer must publish contact details, availability and an assignment/review policy. Target acknowledgement within one working day is a proposed service goal, not a promise already made by the maintainer.
